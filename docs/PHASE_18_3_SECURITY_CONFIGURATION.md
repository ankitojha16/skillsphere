# SkillSphere Phase 18.3 — Security Configuration & Infrastructure Hardening

## 1. Zero-Trust Security Posture & Defense-in-Depth

SkillSphere implements defense-in-depth across the physical, network, container, application, and data layers to satisfy enterprise security compliance:

```
[ Ingress Layer ]     AWS ALB with TLS 1.3, DDoS Shield & WAF
       │
[ Network Layer ]     Multi-AZ VPC with Microsegmented Security Groups
       │
[ Compute Layer ]     Unprivileged Non-Root Linux Containers (UID 1001) with tini
       │
[ Secret Layer ]      AWS Secrets Manager Runtime Injection (Zero Secrets in Git)
       │
[ Storage Layer ]     AES256 Server-Side Encryption, Versioning & Public Block
```

---

## 2. Microsegmented Security Groups & Ingress Matrix

Each infrastructure tier is isolated by stateful AWS Security Groups enforcing strict least privilege:

| Security Group | Ingress Source | Port / Protocol | Egress Destination | Security Objective |
| :--- | :--- | :--- | :--- | :--- |
| **`alb_sg`** | `0.0.0.0/0` | Port 80 (HTTP $\rightarrow$ HTTPS redirect)<br>Port 443 (HTTPS / TLS 1.3) | `ecs_web_sg` on Port 8000 | Only public-facing entrypoint in the entire architecture. |
| **`ecs_web_sg`** | `alb_sg` only | Port 8000 (TCP) | RDS, Redis, S3 (HTTPS), CloudWatch | Drops all direct internet inbound traffic. |
| **`ecs_worker_sg`**| None (No inbound) | None | RDS, Redis, S3 (HTTPS), CloudWatch | Worker daemons originate egress outbound connections only. |
| **`rds_sg`** | `ecs_web_sg`<br>`ecs_worker_sg` | Port 5432 (PostgreSQL) | None | PostgreSQL is inaccessible from the public internet or ALB. |
| **`redis_sg`** | `ecs_web_sg`<br>`ecs_worker_sg` | Port 6379 (Redis) | None | In-memory cache is accessible strictly to application tasks. |

## 3. Container Runtime Hardening

- **Non-Root Execution**: Container images drop privileges in the final multi-stage layer to user `skillsphere:skillsphere` (UID `1001`, GID `1001`).
- **Zombie Process Reaping**: `tini` runs as PID 1 (`ENTRYPOINT ["/usr/bin/tini", "--"]`) to ensure orphaned child processes and asynchronous threads are reaped cleanly upon worker termination.
- **Read-Only Compatibility**: Application runtime does not write to the container root filesystem; temporary files are restricted to `/tmp` and persistent assets to S3.

---

## 4. Secret Management & Identity Control

- **Zero Plain-Text Credentials**: Neither database passwords, Redis secrets, nor Django `SECRET_KEY` are stored in `.env` files or Git repositories.
- **AWS Secrets Manager Integration**: ECS Task Definitions reference secret ARNs (`secrets = [{ name: "DATABASE_URL", valueFrom: "arn:aws:secretsmanager:..." }]`), which are decrypted at task launch directly into environment variables.
- **IAM Task Role vs Execution Role**:
  - `ecs_execution_role`: Limited strictly to pulling ECR images and emitting CloudWatch logs.
  - `ecs_task_role`: Granted minimal S3 permissions (`s3:PutObject`, `s3:GetObject`, `s3:DeleteObject`) scoped strictly to the `skillsphere-staging-media/*` prefix.

---

## 5. Storage Security & Pre-Signed Access Control

- **Public Access Block**: `aws_s3_bucket_public_access_block` enforces `block_public_acls = true`, `block_public_policy = true`, `ignore_public_acls = true`, and `restrict_public_buckets = true`.
- **Encrypted at Rest**: S3 default encryption uses `AES256` or customer-managed AWS KMS keys.
- **Pre-Signed Offloading**: Private certificates and student resumes are served exclusively via cryptographically signed SigV4 URLs generated by `services/storage_service.py` with 1-hour expiration limits.
